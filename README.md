# Project Estimate Builder

Мини-приложение для расчёта стоимости digital-проекта и подготовки черновика коммерческого предложения.

## Стек

| Слой | Технологии |
|---|---|
| **Backend** | Node.js 20, TypeScript, Express, Prisma ORM, SQLite |
| **Frontend** | React 18, TypeScript, Vite |
| **Тесты** | Vitest (unit + integration) |
| **Инфраструктура** | Docker, Docker Compose |

---

## Быстрый старт

### Вариант 1 — Локально

```bash
# Backend
cd backend
npm install
copy .env.example .env       # Windows
# cp .env.example .env       # Mac/Linux
npx prisma migrate dev --name init
npm run db:seed
npm run dev          # → http://localhost:3000
```

```bash
# Frontend (второй терминал)
cd frontend
npm install
npm run dev          # → http://localhost:5173
```

> В dev-режиме Vite проксирует `/api/*` на `:3000`, поэтому открывайте фронтенд на `5173`.

### Вариант 2 — Docker

```bash
docker compose up --build
```

Приложение доступно на **http://localhost:3000** (фронтенд + бэкенд на одном порту).
Seed-данные заливаются автоматически при старте контейнера.

### Вариант 3 — Продакшн (Railway)

Приложение задеплоено и доступно по ссылке:

**https://project-estimate-builder-production.up.railway.app/**

Деплой настроен через GitHub: любой push в `main` автоматически обновляет прод.
При старте контейнера автоматически накатываются миграции и заливаются seed-данные.

## Seed-данные

```bash
cd backend
npm run db:seed
```

Создаёт:
- **5 клиентов** — разные компании
- **8 проектов** — все типы и статусы
- **15 услуг** — все 9 категорий (design, frontend, backend, cms, seo, analytics, integration, support, management) + 1 неактивная

## Тесты

```bash
cd backend
npm test
```

**22 теста в 2 файлах:**

`tests/estimateCalculator.test.ts` — unit-тесты чистой бизнес-логики:
- расчёт стоимости с коэффициентами сложности (low/medium/high)
- округление сроков вверх (`Math.ceil`)
- скидка, наценка, ограничение скидки ≤ 30%
- расчёт маржинальности
- предупреждение `low_margin_warning` при марже < 25%
- блокировка при пустом списке услуг
- блокировка при выборе неактивной услуги
- блокировка когда цена < себестоимости
- блокировка когда срок < 3 дней

`tests/estimateVersioning.test.ts` — интеграционные тесты на отдельной тестовой БД:
- первый расчёт получает версию 1
- второй получает версию 2, третий — 3
- версии независимы между разными проектами
- БД не позволяет создать дубликат версии для одного проекта

## Архитектурные решения

**SQLite вместо PostgreSQL** — задание подчёркивает автономность. SQLite не требует отдельного сервиса, база — это один файл. Для задачи этого достаточно, решение легко мигрировать на Postgres заменой одной строки в `schema.prisma`.

**Бизнес-логика отдельно от роутов** (`src/services/estimateCalculator.ts`) — чистые функции без зависимости от Prisma и Express. Можно тестировать без поднятия БД и HTTP-сервера. Это сознательное архитектурное решение, а не просто «так вышло».

**Zod на входе** — вся валидация входящих данных на границе системы. Zod-схема одновременно служит документацией к API и гарантирует типобезопасность внутри обработчиков.

**Warnings как JSON-строка** — SQLite не поддерживает нативные массивы. Храним `JSON.stringify(['low_margin_warning'])`, при отдаче парсим. Компромисс между простотой и правильностью — для Postgres заменили бы на нативный массив.

**Версионирование расчётов** — при создании нового расчёта backend находит максимальную версию в БД и инкрементирует. Уникальный составной индекс `(projectId, version)` на уровне БД гарантирует отсутствие дублей даже при гонке запросов.

**Frontend через Vite proxy** — в dev-режиме запросы `/api/*` проксируются на `:3000`. В production backend раздаёт собранный React как статику с одного порта — никакого CORS.

## Затраченное время

~ 3 часа с использованием Claude Code как основного инструмента разработки.

Из них:
- ~0,5 ч — проектирование схемы БД, архитектура роутов
- ~1 ч — backend: бизнес-логика, все endpoints, тесты
- ~0,5 ч — frontend: все страницы, формы, валидация
- ~1 ч — итерации по замечаниям (валидация телефона, статус расчёта, расширение seed, доработка тестов)
