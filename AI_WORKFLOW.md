# AI Workflow

## 1. Какие AI-инструменты использовались

- **Claude Code (claude-sonnet-4-6)** — основной инструмент. Использовался в интерактивном режиме через CLI прямо в рабочей директории проекта.

## 2. Какие задачи отдавались AI

- Генерация всей структуры проекта (package.json, tsconfig, vite.config)
- Prisma-схема по ТЗ
- Skeleton всех Express-роутов
- React-компоненты (страницы, формы, таблицы)
- CSS без фреймворков — глобальные стили
- Seed-данные по ТЗ
- Dockerfile + docker-compose.yml
- Заготовки тест-кейсов

## 3. Какие промпты сработали хорошо

- Описание ТЗ целиком в одном сообщении — AI сразу понял контекст и предложил конкретный стек
- «Создай отдельный модуль `estimateCalculator.ts` с чистыми функциями для бизнес-логики» — получился правильно изолированный модуль без зависимости от Prisma/Express
- «Напиши тесты Vitest для всех ограничений из ТЗ» — AI покрыл все кейсы из раздела "Правила и ограничения"

## 4. Где AI ошибался

- **Dockerfile**: первая версия пыталась запустить `ts-node` в production-образе, не компилируя TypeScript. Пришлось переделать на multi-stage build с отдельным этапом компиляции.
- **Seed**: AI использовал `create` вместо `upsert`, из-за чего повторный запуск seed падал на уникальных полях.
- **warnings в SQLite**: AI изначально объявил поле как `String[]` (Prisma-массив), который не поддерживается в SQLite. Исправлено на `String @default("[]")` с ручным JSON.stringify/parse.

## 5. Что было исправлено вручную

- Prisma-схема: убраны enum-типы (в SQLite Prisma хранит их как строки, но это добавляло лишний шум), оставлены plain String с комментариями
- Dockerfile: переработан multi-stage build
- Seed: заменены `create` на `upsert` для идемпотентности
- Тест `totalDays < 3`: AI не добавил этот кейс сразу — дописан вручную после перечитывания ТЗ

## 6. Архитектурные решения, принятые самостоятельно

- **Бизнес-логика отдельно от роутов** (`estimateCalculator.ts`): AI изначально встраивал расчёт прямо в роут. Я выделил это в pure function — легче тестировать и переиспользовать.
- **SQLite**: выбор сделан сознательно — задание подчёркивает автономность, PostgreSQL создаёт внешнюю зависимость без пользы.
- **Warnings хранятся в estimate**: решение хранить `low_margin_warning` в расчёте (а не вычислять на лету при каждом запросе) сделано сознательно — исторические расчёты должны сохранять своё состояние.
- **Frontend через Vite proxy**: упрощает конфигурацию CORS в dev и позволяет в production раздавать всё с одного порта.

## 7. Как проверялось качество результата

- Запуск тестов: `npm test` — все кейсы зелёные
- Ручная проверка через UI: создание клиента → проекта → выбор услуг → расчёт → проверка маржи и предупреждений
- Проверка граничных случаев через curl: скидка 31% (должна вернуть 400), неактивная услуга, пустой список услуг
- Проверка аналитики после seed — цифры сходятся

## 8. Что не доверялось AI

- **Финальная бизнес-логика расчёта** (`calculateEstimate`): формулы из ТЗ проверял построчно сам — это критическая часть, ошибка здесь сломала бы все цифры.
- **Порядок применения ограничений**: AI путался с тем, к какой сумме применяется проверка скидки (к `complexityTotal`, а не к `baseTotal`). Исправлено вручную.
- **Миграции Prisma**: схему генерировал AI, но финальную версию перед `migrate dev` проверял сам — особенно связи и onDelete.
